# Codex Build Instructions: Quirkle Companion

## Project Goal

Create a lightweight, phone-optimized web app for keeping score during a game of Quirkle / Qwirkle.

The app should be simple, fast, tactile, and easy to use during live tabletop play. It should understand the scoring flow of Quirkle and reduce the need for paper scorekeeping.

Primary use case: one person opens the app on their phone or browser and tracks all players’ scores during the game.

# Scoring Rules to Implement

## Normal Turn

Each turn, a player scores a non-negative number of points.

Examples:

0 points = player reset/exchanged tiles
1+ points = normal scoring

The user should enter the total points for that turn, not each tile individually.

## Qwirkle Button

A Qwirkle is worth a bonus.

In Qwirkle rules, completing a line of 6 scores:

6 points for the tiles
+ 6 bonus points
= 12 total points

For this app, implement Qwirkle scoring as an easy button.

The interface should support:

- Entering normal score manually
- Adding Qwirkle bonus
- Making it obvious whether the score entered already includes the Qwirkle total or not

Recommended MVP behavior:

Have a button labeled:

Qwirkle +6

When tapped, it adds 6 bonus points to the current turn score.

Example:

User enters 6
User taps Qwirkle +6
Current turn total becomes 12
User taps Enter

This avoids ambiguity.

Also include one convenience button:

12 Qwirkle

This sets the current score to 12 if the player scored a single standard Qwirkle line.

This allows fast entry.

## Reset Hand / Exchange Tiles

If a player exchanges tiles or resets their hand and scores no points, the score for the turn is:

0

Represent this with a prominent button:

0 / Reset Hand

This sets current turn score to 0.

## First Out / Last Tile Bonus

The game ends when a player plays their last tile.

The player who goes out gets:

+6 bonus points

Implement a button:

Last Tile +6

When selected for the current turn, it adds 6 bonus points to the current player’s submitted turn score and ends the game after submission.

Recommended flow:

Player enters turn score
Player taps Last Tile +6
Player taps Enter
App adds score + 6 bonus
Game locks
Results page displays

# Score Entry Behavior

The score input should work like a calculator/numpad.

## Numpad

Buttons:

7 8 9
4 5 6
1 2 3
0 Clear Enter

Behavior:

- Pressing number buttons appends digits.
- Empty input plus 5 becomes 5.
- 1 then 2 becomes 12.
- Leading zeros should be avoided.
- Clear resets current input to empty or 0.
- Enter submits the current turn.

## Keyboard Support

Also support physical keyboard input for browser dev:

- Number keys append digits
- Enter submits
- Backspace deletes last digit
- Escape clears

## Current Turn Score

Internally track:

currentInputValue
qwirkleBonusApplied
lastTileBonusApplied
currentTurnTotal

Possible simplified model:

baseTurnScore = Number(inputValue || 0)
qwirkleBonus = qwirkleBonusApplied ? 6 : 0
lastTileBonus = lastTileBonusApplied ? 6 : 0
turnTotal = baseTurnScore + qwirkleBonus + lastTileBonus

Display should clearly show this.

Example:

Base: 6
Qwirkle: +6
Last Tile: +0
Turn Total: 12

But keep UI clean. Maybe show details only when bonuses are active.

# Turn Submission

When the user taps Enter:

1. Determine current player.
2. Calculate turn total.
3. Add turn total to current player’s total score.
4. Record the turn in score history.
5. If Last Tile was selected:
   - End game.
   - Lock scores.
   - Move to Results screen.
6. Otherwise:
   - Clear current turn input.
   - Clear Qwirkle bonus.
   - Clear Last Tile flag.
   - Advance to next player.
   - Increment turn counter.

## Turn History Object

Each submitted turn should create an object:

{
  turnNumber: 1,
  roundNumber: 1,
  playerId: "p1",
  playerName: "Sam",
  baseScore: 6,
  qwirkleBonus: 6,
  lastTileBonus: 0,
  turnTotal: 12,
  runningTotal: 42,
  isLastTile: false,
  timestamp: "2026-05-03T..."
}

Round number can be calculated as:

Math.floor((turnNumber - 1) / playerCount) + 1

# Rendering Approach

Use simple conditional rendering in JavaScript.

Recommended:

function render() {
  const app = document.getElementById("app");

  if (state.screen === "start") renderStart(app);
  if (state.screen === "playerCount") renderPlayerCount(app);
  if (state.screen === "names") renderNames(app);
  if (state.screen === "order") renderOrder(app);
  if (state.screen === "game") renderGame(app);
  if (state.screen === "results") renderResults(app);
}

Keep all screen rendering functions in app.js.

The app should be:

- Simple
- Clear

- Calm

Visual style:

# Validation Rules

## Player Count

Must be 2, 3, or 4.

## Player Names

If empty, use default names.

## Score Input

Allowed:

- 0
- Positive integers

Disallowed:

- Negative numbers
- Decimals

For MVP:

Empty input = 0

## Last Tile

If Last Tile is selected, the app ends the game on Enter.

User does not need a confirmation modal in MVP, but the button should visibly toggle on/off before Enter.
